# ☁️ Cloud Learning Journey: Zero to Cloud Support Engineer
Welcome to my public engineering log! I am executing a 12-month career pivot into tech with **zero prior technical background**, learning entirely from scratch through practical, terminal-driven labs and daily documentation.

**Philosophy:** Study theory only to explain what happens in the terminal. Every concept gets hands-on validation before it's considered "learned."

---
## 🗺️ The 12-Month Master Roadmap
* **🟢 Phase 1: Networking Fundamentals (Current)** — Mastering the mechanics of the internet (OSI, TCP/IP, Subnetting, Routing, and CLI diagnostics) aligned with CompTIA N10-009.
* **🟡 Phase 2: Cloud Implementation (AWS)** — Translating networking concepts into cloud infrastructure (VPCs, EC2, S3, IAM) via AWS.
* **🟠 Phase 3: Linux & OS Administration** — Mastering cloud OS architecture, permissions, bash scripting, and system troubleshooting.
* **🔴 Phase 4: Python & Automation** — Automating cloud tasks and API interactions.
* **🟣 Phase 5: Advanced Troubleshooting & Capstone** — Simulating real-world Cloud Support tickets, breaking/fixing environments, and building a final architecture portfolio.
* **🔵 Phase 6: Interview Prep & Job Hunt** — Resume refinement, mock interviews, and applying for Cloud/IT Support roles.

---
## 🛠️ The Workbench Stack
* **OS:** macOS (CLI-driven workflow)
* **Toolkit:** `ping`, `arp`, `netstat`, `traceroute`, `dig`, `curl`, `tcpdump`, `nmap`
* **Workflow:** Daily Markdown logs committed directly to GitHub (`~/cloud-learning-journey/`) to maintain a verifiable proof-of-work history.

---
## 📖 How to Follow Along
1. **Daily Structure:** Each day's folder contains:
   - `day-XX.md` — structured notes (Key Concepts, Hands-on Lab, Key Takeaway)
   - Reproducible terminal commands
   - Lessons learned & blockers overcome
2. **GitHub Commits:** Every day gets pushed with a descriptive commit message (`docs: day-XX topic-name`)
3. **No Prerequisites:** Each phase builds on the last, but can stand alone for reference
